# 一、项目定位

这个项目现在已经从最初的“尝试做一个反馈页”推进到了一个**可实际使用的轻量反馈管理系统**。

目标场景是：

- 面向小规模用户，大约 20 人左右
- 用于收集用户反馈、Bug、功能建议和体验问题
- 长期运行约 10 个月，后续可继续维护
- 不依赖 CloudBase AI Builder
- 使用 CloudBase 基础能力手动搭建
- 尽量低成本、低维护、高可控
- 面向中国大陆访问环境

整体架构是：

```text
用户提交页
  ↓
CloudBase HTTP 访问服务
  ↓
云函数
  ↓
文档型数据库

管理页
  ↓
CloudBase HTTP 访问服务
  ↓
管理云函数
  ↓
文档型数据库
```

# 二、目前使用的技术方案

## 前端

使用纯静态 HTML / CSS / JavaScript。

目前包含：

```text
/index.html        用户反馈提交页
/admin/index.html  管理页
```

优点是：

- 不需要构建工具
- 不需要 npm / React / Vue
- 可直接通过 CloudBase 静态网站托管部署
- 易于修改和维护

## 后端

使用 CloudBase 云函数，配合 HTTP 访问服务暴露接口。

目前已经有：

```text
submitFeedback
adminListFeedback
adminUpdateFeedbackStatus
adminDeleteFeedback
```

## 数据库

使用 CloudBase 文档型数据库。

集合：

```text
feedback
```

权限选择：

```text
ADMINONLY
```

也就是用户不能直接读写数据库，所有数据操作都必须经过云函数。

## 数据结构

目前反馈数据大致包含：

```json
{
  "_id": "反馈 ID",
  "type": "反馈类型",
  "title": "标题",
  "content": "详细内容",
  "contact": "联系方式",
  "images": [],
  "status": "new",
  "createdAt": "提交时间"
}
```

其中 `images` 目前保留为空数组，暂时不使用 CloudBase 原生图片上传。

# 四、已经完成的管理页功能

## 1. 管理密码保护

管理页本身是静态页面，但真正的权限校验在云函数中完成。

流程是：

```text
管理页输入密码
  ↓
前端把密码随请求发送给云函数
  ↓
云函数校验密码
  ↓
校验通过后执行读取 / 修改 / 删除
```

已经明确：

- 前端不保存正确密码
- 密码验证由云函数完成
- 前端只负责传递输入的密码
- 管理页密码输入框已改为普通提示，不再暗示真实密码

这是轻量级保护方案，适合你当前的小规模个人项目。

## 2. 加载反馈列表

管理页可以通过 `adminListFeedback` 加载反馈数据。

已实现：

- 输入管理密码
- 点击加载反馈
- 从数据库读取反馈列表
- 按时间倒序展示
- 展示 ID、类型、标题、内容、联系方式、状态、时间

## 3. 修改反馈状态

已完成状态修改功能。

状态包括：

```text
new          新反馈
reviewed     已查看
resolved     已解决
notplanned   暂不处理
```

其中 `notplanned` 是你自己扩展加入的状态，目前运行正常。

管理页可一键把反馈设置为：

- 新反馈
- 已查看
- 已解决
- 暂不处理

## 4. 删除反馈

已完成删除功能。

流程是：

```text
点击删除
  ↓
确认弹窗
  ↓
调用 adminDeleteFeedback
  ↓
云函数校验密码
  ↓
删除数据库对应记录
  ↓
刷新列表
```

之前出现过“密码错误”，原因是删除云函数中的密码字段忘记修改，目前已修复并运行正常。

## 5. 链接自动识别

管理页已经支持把详细内容中的 URL 自动渲染为可点击链接。

这对现在的“截图链接写在详细内容中”非常有用。

同时也做了基础 HTML 转义，避免把用户输入直接原样塞进 `innerHTML` 带来风险。

## 6. 筛选和搜索

管理页已经支持：

- 按状态筛选
- 搜索关键词
- 只看新反馈
- 重置筛选

搜索范围包括：

- 标题

这部分是前端本地筛选，不需要新增后端接口。

## 7. CSV 导出

管理页已经支持导出 CSV。

特点：

- 导出当前筛选结果
- 支持中文
- 文件名包含日期
- 内容做了 CSV 转义
- 可用于备份、Excel 查看或后续迁移

## 8. 顶部统计概览

统计内容包括：

# 五、目前已经解决过的问题

## 1. Cloudflare 访问不稳定

你最初尝试过 Cloudflare，但面向中国大陆访问不理想。后来我们判断：

- Cloudflare 不适合作为当前反馈系统主服务
- CloudBase 更适合作为中国大陆访问场景的主方案

## 2. CloudBase AI Builder 不稳定

你原来用 AI Builder 生成过应用代码，但管理页功能遇到问题。

我们最终决定：

- 不继续依赖 AI Builder
- 只使用 CloudBase 基础能力
- 重新搭建轻量可控版本

## 3. 文档型数据库权限选择

数据库权限最终选择：

```text
ADMINONLY
```

原因是反馈数据包含联系方式、内容等隐私信息，不应允许用户直接读取或修改。

## 4. 静态网站部署路径问题

曾出现：

```text
/admin     打开旧页面
/admin/    打开正确页面
```

最终决定统一使用：

```text
/admin/
```

并把管理页放在：

```text
admin/index.html
```

## 5. 云函数依赖问题

使用 `@cloudbase/node-sdk` 时，云函数日志提示缺依赖。

解决方式是为相关云函数添加 `package.json`：

```json
{
  "dependencies": {
    "@cloudbase/node-sdk": "latest"
  }
}
```

之后函数正常运行。

## 6. HTTP 路由与 API 地址问题

你曾遇到管理页“请求失败”，后来检查 F12 发现是 API 地址填写错误。

修正后管理页正常加载。

## 7. 图片上传复杂度问题

我们原本讨论过 CloudBase 云存储上传，但发现需要处理：

- 匿名登录
- 安全来源
- Web SDK
- 云存储权限
- CORS
- 文件大小限制

最终决定暂不做原生上传，而是让用户把图床链接写在详细内容中。

这个决策降低了很多复杂度。

# 八、当前仍然存在的局限

## 1. 管理密码是轻量级方案

它适合你现在的个人项目，但不是完整认证系统。

如果后续多人管理或安全要求提高，应该换成：

- CloudBase 登录
- 管理员账号
- Token
- 白名单
- 更严格的鉴权

## 2. 数据分页还没做

目前管理页一次最多加载一定数量的反馈，之前云函数中可能使用了 `.limit(50)` 之类的限制。

如果以后反馈变多，需要做：

- 分页加载
- 按时间加载更多
- 后端筛选

## 3. 图片没有本地上传

现在通过图床链接解决。

优点是简单，缺点是：

- 用户需要自己上传图片
- 外部链接可能失效
- 无法统一管理附件

但对当前阶段是合理取舍。

## 4. 暂无通知机制

目前有新反馈后，需要你手动进入管理页查看。

如果后面想更方便，可以做：

- 邮件通知
- 微信 / Telegram / Server 酱通知
- Webhook 推送
