# R-002 服务端流式 CSV 导出与操作审计

## Goal

让管理员导出反馈/WorkTask 时不再依赖浏览器收集全部分页数据，并为高影响的管理操作留下可查询、脱敏、可保留的追责记录；核心业务继续使用现有 Express、原生静态页面和 SQLite/MySQL/PostgreSQL 适配，不引入新的队列、ORM 或运行时服务。

## Background and confirmed facts

- 当前导出由 `public/admin/admin.js` 逐页调用管理列表接口，再在浏览器内拼接完整 CSV；列表接口每页最多 100 条，但没有导出专用接口或服务端总量上限。
- 当前反馈/WorkTask 管理路由覆盖列表、状态、删除、主页展示、备注/回复、WorkTask 安排和管理员创建；管理员会话已有 `req.adminUser.id` 与 `req.adminUser.username`。
- 当前数据库 schema 由 `server/db.js` 统一初始化，查询层已抽象为 `queryOne`、`queryAll`、`execute`；尚无通用操作审计表或审计查询接口。
- API 约定为 `{ ok, data }`/统一错误 envelope；管理员路由受会话、同源、JSON 和限流中间件保护。
- 安全边界禁止把 API Key、Token、密码、完整通知载荷或不必要的敏感数据写入日志/导出；管理员导出仍属于受保护的私有数据操作。

## Product requirements

### R2-CSV 服务端导出

- 为反馈和 WorkTask 提供受管理员会话保护的服务端导出接口，复用现有状态、关键词和优先级筛选语义。
- 服务端以有界批次生成 CSV 并逐块返回，浏览器不得先收集全部结果；CSV 保留现有导出的列顺序、UTF-8 BOM、双引号转义和下载文件名。
- 单次导出最大行数由环境变量 `ADMIN_EXPORT_MAX_ROWS` 调整，默认 10,000，代码强制限制在 100–100,000；修改环境变量后需重启服务。超过上限时在开始发送 CSV 前明确拒绝，不允许静默截断。
- CSV 不新增超出现有管理员导出语义的敏感字段；导出请求的审计记录不得包含 CSV 内容、API Key、Cookie 或完整查询结果。

### R2-AUDIT 操作审计

- SQLite、MySQL、PostgreSQL 均增加兼容的审计表，保存审计 ID、时间、管理员快照、动作、实体类型/ID（如适用）、请求 ID、结果和脱敏元数据/错误摘要。
- 默认记录 CSV 导出、反馈/WorkTask 的状态、删除、主页展示、备注/回复、WorkTask 安排、管理员创建，以及 AI 建议接受/拒绝和通知人工重试等高影响管理员动作；不记录登录密码、Cookie、Provider Key 或完整业务内容。
- 提供受管理员保护的分页审计查询接口，支持动作、实体、管理员、时间范围和有界 pageSize 筛选；返回值只包含脱敏字段，并遵循现有 API envelope。
- 审计写入失败不得回滚已成功的业务操作；必须写结构化日志并保持原有业务响应语义。明确的未找到、超限等业务结果也要留下动作级记录；未通过输入校验、未进入业务层的请求继续由现有错误/访问日志处理。
- 审计记录采用动作级脱敏元数据，不保存 before/after 全文、CSV 内容、联系方式、Cookie 或密钥，随数据库备份策略保留，不新增自动清理任务。

## Scope boundaries

- 导出使用应用层固定批次查询并分块写出；反馈与 WorkTask 使用 POST JSON 导出接口。
- 暂不增加复杂审计前端页面；管理员通过 API 排查审计记录，后续如有需要再增加页面。
- 不承诺跨并发写入的事务快照，不引入数据库游标依赖、异步导出任务、临时文件清理系统或新的技术栈。

## Acceptance criteria

- [ ] 反馈和 WorkTask 导出由服务端生成，浏览器不再分页拉取并拼接全量列表；筛选、列顺序、BOM、转义、文件名和响应头有回归覆盖。
- [ ] `ADMIN_EXPORT_MAX_ROWS` 默认与边界值可验证；超过上限返回稳定的 `413 EXPORT_LIMIT_EXCEEDED`，正常导出按批次写出且不构造全量数组。
- [ ] 三种数据库 schema 均包含审计表；旧 SQLite 数据库可幂等启动并读写审计记录。
- [ ] 规定的管理员动作生成脱敏审计记录；审计写入失败只记录日志、不改变业务成功/失败语义；审计查询支持权限、分页和筛选。
- [ ] 管理员页面改用服务端下载，成功/错误状态可见；亮暗主题、键盘操作和窄屏布局不回归。
- [ ] 相关 Node 语法检查、聚焦测试、完整 `npm test`、`npm audit --omit=dev --registry=https://registry.npmjs.org`、`git diff --check` 和 Trellis 质量检查通过。
- [ ] API、架构、运维、配置、功能状态、路线图、发布门禁和已知缺陷文档同步，明确环境变量、审计保留和回滚方式。

## Risks and deferred verification

- `COUNT` 与分批读取之间可能发生数据新增/删除；本任务只保证有界、可追踪的导出，不提供长事务快照。需要强一致快照时另行设计。
- 当前本地主要验证 SQLite；MySQL/PostgreSQL 的真实连接矩阵仍属于 V-005，至少需对 schema 与参数化 SQL 做静态检查，并在有隔离环境时再做实链路验证。
