# KWS UI与文案整理

## Goal

在不改变现有 API、数据库、权限边界和页面技术架构的前提下，整理管理员面板、公开项目主页和项目详情的布局与中文文案，使信息层级更清晰、控件不再挤压或错位，并继续保持冷色、直角、亮暗主题和响应式可用性。

## Background and confirmed decisions

- 当前前端为静态 HTML/CSS/JavaScript：管理员结构在 `public/admin/index.html`，交互在 `public/admin/admin.js`，共享样式在 `public/workstation.css`；公开主页使用 `public/index.html` 与 `public/index/main.js`，公开项目详情使用 `public/project/index.html` 与 `public/project/main.js`。
- 截图和代码检查确认：SMTP/Webhook 测试、MeowStatus、Minecraft 展示、AI Copilot 配置集中在管理员页面顶部，AI 字段使用单一 flex 行导致挤压；本人任务录入分组不足；知识助手问题框使用了 TYUTland 特定示例；公开项目卡片把整个项目作为链接并带有不需要的下划线/混合层级。
- 布局方案已确认：管理员使用独立“设置”选项卡；公开项目使用分隔列表，项目名称和说明为普通文本，只有“查看详情”作为跳转入口。
- 设置选项卡放在现有业务选项卡末尾，顺序保持为：工作收件箱 → 反馈 → WorkTask → 本人任务录入 → 项目 → 知识助手 → 设置。
- 术语已确认：原词“Feedback 泳道”“WorkTask 泳道”统一改为“反馈分区”“WorkTask 分区”；Kanban 分区标题也使用“分区”。
- 首页徽标已确认由“`KWS Simple Entry`”改为“`KWS Work Hub`”。
- 用户可见文案统一使用“AI 配置”，包括“当前 AI 配置”“编辑 AI 配置”“删除 AI 配置”；API、DOM id、数据库字段和代码变量继续保留 `profile` / `profileId`。
- 保留现有 Node + Express + 静态页面 + 原生 JavaScript 技术栈；不引入框架、构建步骤、数据库迁移或新路由。

## Requirements

### R1. 管理员设置信息架构

- 在管理员业务选项卡末尾新增“设置”选项卡和对应模块。
- 将 SMTP 测试、Webhook 测试、MeowStatus 状态展示设置、Minecraft 状态展示设置、AI Copilot 配置/配置列表/真实诊断/指标移入设置模块；原有 DOM id、API 路径、按钮 busy/错误提示和权限行为保持兼容。
- 业务选项卡区域只保留工作收件箱、反馈、WorkTask、本人任务录入、项目、知识助手和设置；设置模块未选中时不占用业务模块的视觉空间。
- 知识库索引、知识问答和问答历史/自动清理属于知识助手本身，继续放在知识助手模块，不复制到全局设置。

### R2. AI Copilot 配置可读性

- 将 profile 表单从单行 flex 改为明确的标签/字段网格：名称、协议、Base URL、模型、推理强度、API Key 各自拥有稳定列宽，在窄屏时按单列堆叠。
- 附加工作指令和协议提示保持整行；配置列表、诊断和指标各自有清晰的区块标题与间距。
- 将按钮文案“保存 profile”改为“保存配置”；其余多 profile、active 切换、`reasoning_effort`、自定义指令和真实诊断功能不改变。
- AI 配置列表、诊断和状态文案不得再向用户展示裸的 `profile` 或 `active profile`；技术文档首次出现可写作“profile（AI 配置）”。

### R3. 管理员项目详情和术语

- 调整项目编辑表单、公开设置、完成度、视图切换、里程碑新增表单的分组和间距，避免字段、标签和按钮横向挤压；保留现有项目公开开关和 A+C 完成度行为。
- 关系视图标题使用“反馈分区”和“WorkTask 分区”；Kanban 分区标题使用同样术语；添加入口使用“添加反馈”和“添加 WorkTask”。
- 保留两类来源的独立状态模型、绑定/解绑和状态保存 API，不把两类来源合并为同一状态流。

### R4. 主页公开项目展示

- 公开项目改为与主页其他模块一致的方框列表/分隔层级；每个项目有明确边界、足够内边距和稳定的标题/说明换行。
- 项目名称和说明使用普通文本，不包含链接行为或默认下划线；仅“查看详情”作为明确的 `<a>`/按钮入口并保留编码后的公开 key。
- 长中文、英文和混合标题/说明不得造成水平溢出；窄屏自动单列，亮暗主题均保持对比度和焦点状态。

### R5. 其他文案与布局

- “本人任务录入”按任务基本信息、时间/负责人、标签、说明、对外/内部备注、提交操作分组，增加可读间距并保留现有字段和 API payload。
- 知识助手问题框 placeholder 改为通用提示，不出现 TYUTland 或其他特定知识库示例。
- 首页徽标改为“`KWS Work Hub`”。
- 当前产品/运维/测试文档中描述本功能的“泳道”同步改为“分区”；归档任务的历史设计记录不为追求措辞一致而改写。

## Acceptance Criteria

- [ ] 登录管理员后，设置相关控件只在“设置”选项卡出现；切换到收件箱、反馈、WorkTask、本人任务录入、项目、知识助手时不重复显示；SMTP/Webhook、状态设置、AI 保存/切换/诊断/指标行为和 API 契约保持可用。
- [ ] AI profile 表单在桌面和 620px 左右窄屏均按稳定网格显示，不出现字段被挤成不可读宽度；按钮显示“保存配置”。
- [ ] AI 配置相关用户可见文案统一为“AI 配置”，不出现“保存 profile”“active profile”等混合表述；接口和代码字段仍兼容原有命名。
- [ ] 项目详情在桌面、窄屏、亮色和暗色主题下，编辑/公开设置/完成度/里程碑/视图切换均有清晰分组；界面中不再出现“泳道”，对应位置使用“反馈分区”“WorkTask 分区”。
- [ ] 主页公开项目列表中，项目名称和说明不能触发跳转或显示默认下划线；仅“查看详情”可导航到正确的 `/project/?key=...`，长文本无水平溢出且项目之间有明显分隔。
- [ ] “本人任务录入”不再把所有字段挤在同一行；知识助手问题 placeholder 为通用提问提示；主页徽标显示“`KWS Work Hub`”。
- [ ] 所有动态文本继续经过现有转义/textContent 边界；按钮保留显式 `type`、键盘焦点、busy/错误恢复和 `aria-live` 状态。
- [ ] 运行相关静态 UI/model 测试、所有变更 JavaScript 的 `node --check`、`git diff --check`，并完成管理员/主页/公开项目页的亮暗主题、键盘和窄屏手工冒烟。

## Out of scope

- 不修改服务器 API、数据库 schema、AI Provider 协议、知识库索引逻辑、认证权限或公共隐私 allow-list。
- 不推进 KyanetAccount 联动，不新增前端框架、组件库、构建步骤或独立设置路由。
- 不把知识助手的历史清理设置复制到全局设置，也不改变知识问答提示词或回答行为。
- 不重写归档任务中的历史设计/计划文档；只更新当前有效的产品、运维、测试和项目规范引用。

## Open questions

- 无阻塞性的产品决策；技术实现细节在 `design.md` 和 `implement.md` 中确定，并在用户审阅后才进入执行阶段。
