# Work Hub 总览增强

## Goal

在现有管理员工作收件箱、项目容器和 Kanban 基础之上，增加一个独立的 Work Hub
总览，让管理员能快速判断“现在需要处理什么”。总览聚合现有 Feedback/WorkTask
数据，突出逾期、近期计划、未分配和最近更新，并从摘要进入既有管理详情；不改变
两类来源的业务表或状态语义。

## Background and confirmed facts

- 管理面板目前有工作收件箱、Feedback 管理、WorkTask 管理、本人任务录入、项目、
  知识助手和设置标签。
- 收件箱分别请求 Feedback/WorkTask 列表接口；列表按创建时间分页，单类一次最多
  加载 100 条近期记录，详情操作在收件箱中复用既有处理逻辑。
- 项目关系存储在 `project_item`，每个来源最多归属一个项目；项目详情已有项目、
  里程碑及按来源分开的安全摘要，管理员项目详情支持 hash 导航。
- Feedback 没有负责人或计划时间字段；WorkTask 有 `assignee`、`scheduledAt`、
  `status`、`priority` 和 `updatedAt`，因此“未分配”“逾期”“近期计划”均以
  WorkTask 为主，Feedback 只参与最近更新。
- 当前只有单管理员会话；不推进 KyanetAccount 联动、匿名历史查询或公共 Kanban。
- 技术基线保持 Node.js 24、Express 4、现有 SQLite/MySQL/PostgreSQL 数据库抽象、
  静态 HTML/CSS/JavaScript；不引入前端框架、ORM、实时服务或新外部服务。

## Requirements

### R1. 入口与导航

- 新增独立的管理员“Work Hub”标签和模块；默认登录入口仍保持现有工作收件箱，
  不替换收件箱。
- Work Hub 与收件箱、Feedback/WorkTask 专项管理、项目详情之间提供清晰跳转。
- 摘要操作应能定位到既有管理详情：对 Feedback/WorkTask 复用现有列表/详情渲染
  与操作逻辑，对项目使用现有项目 hash 详情；不创建第二套编辑或状态保存逻辑。

### R2. 关注分区与规则

- 提供四个分区：逾期、近期计划、未分配、最近更新。
- 固定时间窗口和上限：
  - 逾期：WorkTask 的 `scheduledAt` 早于请求生成时刻，且状态不是
    `completed`/`cancelled`。
  - 近期计划：WorkTask 的 `scheduledAt` 位于 `[请求时刻, 请求时刻 + 7 天)`，
    且状态不是 `completed`/`cancelled`。
  - 未分配：WorkTask 的负责人为空或全为空白，且状态不是
    `completed`/`cancelled`。
  - 最近更新：Feedback 与 WorkTask 的 `updatedAt` 位于最近 7 天，包含其原生状态。
  - 每个分区最多 10 条；按分区对应时间字段倒序，时间相同按来源类型和 ID 稳定排序。
- 缺失或无效的计划/更新时间不参与相应时间分区，不得被当作逾期或近期项目；
  页面应说明该分区暂无符合条件的记录。
- 每条摘要至少包含来源类型、来源 ID、标题、原生状态、适用的优先级/负责人/计划
  时间、更新时间和项目上下文；未归属项目显示“未归属”。

### R3. 安全数据边界

- 新增管理员只读聚合接口，使用有界、allow-list DTO；不得返回联系方式、管理员备注、
  完整正文、图片、账号 ID/快照、通知载荷或 Provider 凭据。
- 查询使用参数化 SQL，兼容 SQLite、MySQL、PostgreSQL；不改变现有 API 响应。
- 浏览器渲染所有不可信文本时继续使用转义；不新增公共页面数据。

### R4. 加载与降级

- 总览请求应一次返回四个分区及生成时间/规则元数据，不依赖浏览器拼接分页列表。
- Feedback 与 WorkTask 的读取按来源隔离：单一来源失败时其他来源和可用分区仍显示，
  失败分区提供明确的失败/重试提示；不使用上次成功缓存。
- 全部来源失败时显示整页重试提示，但不影响收件箱、提交、通知、项目和其他设置模块。
- 空数据、缺失时间、加载中和请求失败状态均可理解，并保留键盘焦点与主题样式。

### R5. 视觉与兼容

- 延续现有 Work Hub 冷色、亮/暗主题、直角/方框控件和静态页面风格。
- 覆盖窄屏布局、中文长标题、键盘焦点、按钮忙碌态和 aria-live 状态提示。

## Acceptance Criteria

- [ ] 登录管理员可从独立“Work Hub”标签进入总览，并可返回工作收件箱及两个专项管理页。
- [ ] 四个分区严格按 R2 的状态、时间窗口、排序和 10 条上限展示；边界时间、终止状态、
      缺失/无效时间和稳定排序均有测试。
- [ ] 未分配、逾期和近期计划只把适用的 WorkTask 纳入；最近更新可包含两类来源；项目
      上下文与真实 `project_item` 归属一致，未归属项显示“未归属”。
- [ ] 摘要 DTO 和浏览器 DOM 均不包含 R3 禁止字段，文本注入测试通过。
- [ ] Feedback 或 WorkTask 单方读取失败时其他分区仍可用并显示失败分区提示；全部失败时
      可重试，现有模块仍可正常加载。
- [ ] 点击摘要可进入现有来源管理详情或项目 hash 详情，不产生新的写入/状态逻辑。
- [ ] 亮/暗主题、窄屏、键盘操作、加载/空/失败状态通过静态和浏览器回归检查。
- [ ] 修改的 JavaScript 通过 `node --check`，相关 `node:test`、`npm test`、
      `git diff --check`、`task.py validate` 和 canonical 依赖审计通过；不升级 Express
      主版本、不引入 Account 联动或运行时框架。

## Key decisions

- Work Hub 采用独立管理员标签；默认仍进入工作收件箱。
- 采用服务端只读聚合接口；浏览器不通过多个分页列表接口推导总览。
- 时间窗口：逾期与近期计划按请求时刻计算，近期计划为未来 7 天；最近更新为最近 7 天；
  每区最多 10 条。
- 单来源失败按分区降级，不使用旧缓存；全部失败才显示整页重试。
- 总览纳入未归属项目的 Feedback/WorkTask，并以“未归属”标识。

## Out of scope and deferred

- 不新增公共 Work Hub、公共 Kanban、用户侧历史视图或匿名查询。
- 不新增拖拽/批量操作、依赖图、子任务、实时协作、通知编排或新的搜索/报表系统。
- 不推进 KyanetAccount 联动；其重构另建任务。
- 不在本任务中改变来源状态机、项目公开开关、数据库表结构或部署拓扑；若实现发现
  需要 schema 变更，先停在设计审查并另行批准。
