# P2 项目管理基础能力

## Goal

在现有反馈、WorkTask、工作收件箱和公开进展之上提供轻量项目管理能力，让个人及约 20 人以内的
小团队可以按项目组织工作项、跟踪阶段性交付节点并选择性公开进展，同时保持
KyanetWorkStation 的低维护、自托管定位。

## Background and current state

- 当前运行时为 Node.js 24、Express、原生 HTML/CSS/JavaScript；数据库通过 `server/db.js` 支持
  SQLite、MySQL 和 PostgreSQL。现有管理员入口在一个静态页面中以标签切换工作收件箱、Feedback、
  WorkTask、知识助手和设置。
- Feedback 与 WorkTask 是两个独立业务来源。反馈状态为 `new/reviewed/resolved/notplanned`，
  WorkTask 状态为 `new/scheduled/in_progress/completed/cancelled`；收件箱只在读取层合并，不能把
  两种记录转换成同一类型。
- 当前只有单管理员会话模型；KyanetAccount 重构和联动暂停，匿名历史记录不自动认领新账号。
- 公开首页已有反馈/WorkTask 进展和服务状态卡片，公共投影采用显式 allow-list，禁止返回正文、
  联系方式、管理员备注、账号快照或 provider 数据。
- 项目管理是 P2 增量。完整 Kanban、甘特图、实时协作和复杂资源管理不属于本次首版。

## Requirements

### R1. Project container and lifecycle

- 管理员可以创建、编辑、软归档和恢复项目；项目元数据只有名称、可选说明、活跃/已归档状态、
  创建时间和更新时间，不增加项目负责人、成员权限、颜色或独立起止日期。
- 项目归档不删除关系或业务记录，也不冻结 Feedback/WorkTask 自身的状态、备注、通知和其他原生
  操作；归档项目默认从活跃列表和公共端隐藏。
- 归档项目可被管理员查看、编辑、解绑和整理已有关系；新增里程碑或新增工作项绑定前必须先恢复。

### R2. Work item organization

- 采用 A+ 模型：项目是组织层，Feedback 与 WorkTask 仍保留各自原表、字段、状态和处理接口；一个
  来源记录最多归属一个项目，也可以未归类。
- 项目详情分为 Feedback 与 WorkTask 两个泳道，使用各自原生状态，不增加需要同步的项目状态。
- 绑定、换里程碑和解绑均支持从项目详情及来源详情执行；首版只做单条操作，不以批量归属或拖拽
  作为唯一入口。移动到其他项目必须先解绑再绑定，不隐式抢占已有归属。

### R3. Milestones and completion

- 每个项目可有多个轻量里程碑，字段为标题、说明、目标日期、完成标记和排序；里程碑只允许软撤销
  与恢复，不提供硬删除。
- Feedback/WorkTask 可选关联同项目中的一个里程碑；里程碑不跨项目复用，也不改变来源记录状态。
- 撤销里程碑不计入完成度或公共投影，关联工作项保留在项目中并解除里程碑关联；恢复后不会自动
  重新关联。
- 完成度默认按“已完成有效里程碑 / 有效里程碑总数”计算并四舍五入为 0–100 整数；无有效里程碑
  时显示“未设置”。管理员可启用项目级自定义 0–100 值覆盖自动结果，关闭自定义后恢复自动计算，
  自定义值不改变任何里程碑或来源状态。
- 子任务、依赖、任务树、关系图和循环依赖校验延期到独立迭代。

### R4. Administrator experience

- 管理员工作台新增一级“项目”标签；项目列表与详情保持在同一静态页面，详情通过 hash 定位以
  支持刷新及前进/后退。
- 列表默认显示活跃项目，支持全部/活跃/已归档筛选、关键词和分页；卡片显示名称、说明、来源数量、
  里程碑完成度、公开状态和更新时间。
- 详情按元数据/归档、公开设置、里程碑、Feedback 泳道和 WorkTask 泳道分区。写入成功后重新读取
  详情，不依赖乐观更新；冲突时保留用户输入并给出下一步提示。
- 继续使用现有直角冷色视觉、亮暗主题、中文可读性、窄屏布局、键盘焦点和可访问性规则。

### R5. Public visibility and pages

- 项目公开设置至少分四个项目级开关：基础信息（名称/说明）、里程碑、更新时间和完成度；后三个
  详情开关默认关闭，不能由基础信息公开自动推断。
- 公开首页在现有进展和服务状态之间增加“公开项目”区块；没有公开项目时整块隐藏。卡片只显示
  基础名称/说明，并链接到独立 `/project/` 静态详情页。
- 基础信息公开且项目未归档是访问公共详情的前置条件；里程碑、更新时间和完成度按各自开关分别
  渲染，关闭时省略字段。归档、未公开和不存在对公共端统一表现为不可用/404，不泄露具体原因。
- 公开详情不展示任何关联 Feedback/WorkTask 的正文、联系方式、图片、管理员备注、账号快照、
  内部 ID 或原生处理字段。
- 项目保留内部自增 `id`，另生成不可变、不可猜测的随机 `publicKey`；公共列表、链接和 API 只使用
  `publicKey`，改名不改变公开链接。

### R6. API, validation and authorization

- 管理读接口覆盖分页列表、项目详情、来源当前归属和候选工作项；管理写接口覆盖项目生命周期、
  里程碑维护和工作项归属。公共读接口覆盖公开项目列表及按 `publicKey` 的详情。
- 所有管理写请求继续经过管理员会话、同源和 JSON 中间件，使用 `{ok:true,data:...}` 或统一
  `sendError` 错误 envelope；不增加成员、角色或项目级 RBAC。
- 校验名称/标题/说明的 Unicode 长度、正整数 ID、来源 allow-list、ISO 日期、布尔值、排序值和
  0–100 完成度；服务端再次校验来源存在、单项目唯一归属及里程碑同项目关系。
- 常规输入错误为 `400 INVALID_PAYLOAD`，不存在为 `404 NOT_FOUND`，重复归属为
  `409 PROJECT_ITEM_CONFLICT`，跨项目或非法里程碑关联为 `409 PROJECT_MILESTONE_CONFLICT`。

### R7. Privacy, audit and recovery

- 管理员项目投影可包含内部 ID、`publicKey`、公开开关、数量统计、里程碑和来源摘要；来源摘要仅
  包含来源类型/ID、标题、类型、原生状态、必要的优先级/负责人/计划时间和更新时间。
- 公共列表仅返回 `publicKey`、名称和说明；公共详情按开关返回安全字段。所有投影均由服务端
  allow-list 生成，不能把数据库整行直接序列化。
- 项目、里程碑、绑定/解绑、归档/恢复和公开设置动作写入管理员审计；审计只保留 ID、来源类型/ID、
  变更字段、数量和结果等脱敏元数据，不写自由文本正文、密钥或 URL。
- 来源硬删除后清理多态关系；项目详情读取再次过滤并修复孤儿关系。里程碑撤销采用可重复的“先标记
  撤销、再清空关联”流程并记录异常；现有无事务 facade 时不宣称跨写原子性。

### R8. Compatibility and operational behavior

- 新增项目能力不得修改 Feedback/WorkTask 原表字段或破坏管理员收件箱、通知、AI、公开 highlights
  和现有提交接口。
- 数据库通过现有三驱动 schema 和增量初始化创建项目表/索引；旧数据库启动时保留全部历史数据，
  不引入独立 migration runner，不执行破坏性删除。
- 发布顺序为备份、同步代码、启动初始化、管理员/API/浏览器冒烟；回滚旧代码时保留新表并由旧版本
  忽略，只有备份恢复演练确认后才恢复数据库文件。
- 不恢复旧 KyanetAccount 联动，不让 AI 自动创建/修改/删除项目或工作项，不发送额外通知或执行外部命令。

## Acceptance criteria

- **AC-1（R1/R2）**：管理员可创建项目、编辑/归档/恢复，并把 Feedback 与 WorkTask 分别绑定、换
  里程碑和解绑；同一来源无法同时归属两个项目，来源原生状态保持不变。
- **AC-2（R3）**：里程碑可创建、排序、完成、撤销和恢复；撤销会从完成度排除并解除工作项关联，
  恢复不会自动重绑；自动/自定义完成度按规则显示且可切换。
- **AC-3（R4）**：管理员项目标签、列表、hash 详情、来源泳道和单条操作在亮/暗主题、窄屏、键盘
  操作和中文长文本下可用；写入后刷新仍显示数据库真实状态。
- **AC-4（R5/R7）**：公开首页只出现基础信息公开且未归档的项目；公共详情严格按三个详情开关
  省略字段，永不包含正文、联系方式、管理员字段或内部来源 ID；未公开/归档/不存在均不可枚举。
- **AC-5（R6）**：无管理员会话的管理接口被拒绝；非法输入、重复归属、跨项目里程碑和缺失资源返回
  稳定错误 envelope 与错误码；公共与管理员投影均通过字段 allow-list。
- **AC-6（R7/R8）**：SQLite、MySQL、PostgreSQL schema/index 声明等价；旧数据库可增量启动且不丢失
  原有记录；来源删除后的孤儿关系可清理；项目审计不含自由文本敏感字段，旧版本回滚不需删表。
- **AC-7（回归）**：现有反馈、WorkTask、收件箱、通知、AI profile/知识助手、公开 highlights 和
  运行时测试全部通过；新增针对性单元/HTTP/浏览器冒烟和 `git diff --check` 通过。

## Out of scope and deferred

- 子任务、依赖、完整 Kanban/甘特图、实时聊天、文件协作、计费、多租户、复杂 RBAC、通用插件市场。
- KyanetAccount 重构、历史匿名记录自动认领、用户侧/运维侧 AI 和任何 AI 自动业务写操作。
- 逐个里程碑公开开关、项目成员/负责人、颜色、独立开始/目标日期、批量绑定和拖拽作为唯一操作入口。

## Open questions

当前无阻塞的产品或范围问题；后续子任务若改变归档、公开字段、来源类型或 Account 边界，必须重新
进行需求收敛和设计评审。
