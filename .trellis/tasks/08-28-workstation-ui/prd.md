# P1 Workstation 方正冷色 UI 与统一工作收件箱

## Goal

把现有四类静态页面（首页、反馈、WorkTask、管理员面板）整理为一套可持续的
Workstation 视觉与交互系统，并让管理员登录后首先看到可执行的工作收件箱。
目标是提升公开入口的清晰度、后台处理效率和亮/暗主题下的可读性，不改变当前
Node.js + Express + 原生 HTML/CSS/JavaScript 的基本技术架构。

## User value and background

- Workstation 当前已经具备匿名反馈、WorkTask、管理员处理、主页公开进展和
  MeowStatus 状态展示，但页面 CSS 各自内嵌，重复样式较多，页面层级和状态反馈
  不够鲜明。
- 管理员当前默认进入反馈模块，反馈与 WorkTask 需要手动切换；这不符合“工作中枢”
  的入口语义。
- 当前界面存在圆角卡片/按钮/输入框、渐变和模板化卡片密度；用户已确认改为
  方框、方正、棱角明确的设计。
- 未来 AI 辅助仍按路线图单独规划，本任务不引入 Provider、密钥或 AI 网络调用。

## Confirmed product and UX decisions

1. KyanetAccount 暂停联动；本任务不读取、不迁移、不绑定 Account 数据。
2. 公开层和管理员层使用同一视觉 token，但数据权限和信息内容严格分层。
3. 首页是“公开工作入口”，首屏突出反馈与 WorkTask 操作，展示公开进展和服务状态，
   不展示内部备注、联系方式、管理员统计或账号数据。
4. 管理员登录后默认进入“工作收件箱”。
5. 工作收件箱采用统一列表：按更新时间倒序，支持状态、优先级、来源筛选；点击条目
   在列表内联展开安全详情。反馈与 WorkTask 专项视图、本人与任务录入仍保留为次级入口。
6. 视觉方向为冷色技术工作台：浅蓝/蔚蓝/冷灰为主，支持 `theme.js` 的亮暗切换；
   minimalist-flat 为基础，glassmorphism 只用于少量重点面板，Sci-Fi HUD 只用于
   状态/角标，particle 只做低存在感 CSS 氛围。
7. 所有卡片、面板、按钮、输入框、徽标均为矩形，不使用 `border-radius`、胶囊按钮、
   圆形容器或大面积 `clip-path`；Hero、当前导航、服务状态和关键操作可使用少量 L 型
   角标强化方向感。

## In scope

### Shared visual system

- 新增一个无构建步骤的共享样式入口，集中维护亮/暗主题 token、字体栈、间距、边框、
  冷色状态色、焦点环、按钮/表单/通知/空状态/错误状态和响应式基础规则。
- 四个页面加载共享样式；页面保留必要的页面专属布局规则，删除或覆盖冲突的圆角、
  过度阴影、渐变和重复 token。
- 使用语义 HTML、可见焦点、`aria-live` 状态、`prefers-reduced-motion` 降级和窄屏
  单列布局；不引入 React、Tailwind、粒子库、图标库或新的运行时依赖。

### Public pages

- 首页重排为公开工作入口：明确的首屏行动区、反馈/WorkTask 两个主要入口、公开进展
  与服务状态分区、清晰的加载/空/不可用状态。
- 反馈页和 WorkTask 页统一表单层级、字段标签、错误提示、提交中状态和返回导航；
  保持现有 API、字段名、客户端校验和主题切换行为。

### Admin work inbox

- 登录成功后切换至 `inbox` 模块；保留反馈、WorkTask、本人任务录入等专项功能。
- 收件箱通过现有管理员列表 API 获取两类安全 DTO，在页面层合并、按更新时间倒序，
  用来源、状态、优先级和关键词筛选；数据量超过单次来源上限时提供到专项视图的
  明确入口，不伪造“已加载全部”。
- 统一列表条目显示来源、标题、状态、优先级（适用时）、更新时间和最小摘要；详情
  内联展开时继续使用现有状态更新、安排、备注/回复、主页展示和删除操作。
- 保留现有 SMTP/Webhook 测试、状态设置、分页、导出和通知补偿入口，调整其布局以
  区分高频处理与低频运维操作。
- 加入收件箱的加载、空结果、筛选无结果、接口失败、操作成功/失败和键盘焦点状态。

### Defects tracked by this task

- UI-001：四类页面各自内嵌 CSS，token、表单和状态样式重复且易漂移。
- UI-002：圆角/渐变/阴影造成模板化观感，与已确认的方框设计冲突。
- UI-003：管理员默认入口和信息层级仍以模块管理为中心，没有统一工作入口。
- UI-004：空、错误、加载、焦点和窄屏状态的视觉反馈不一致或不够明显。

## Out of scope

- 不修改数据库 schema、认证协议、匿名记录归属、KyanetAccount 联动或后端业务授权。
- 不实现 AI Copilot、模型 Provider、向量检索、知识库、自动回复或自动执行副作用。
- 不新增前端构建系统、框架、状态管理库、外部字体 CDN、图标/粒子运行时或部署平台。
- 不重写现有 API；只有在收件箱确需安全 DTO 边界时才允许增加最小只读路由，且必须
  复用现有查询/会话/错误契约并配套测试。
- 不处理当前发布验收任务尚未完成的真实 PM2 开机恢复、TLS 证书链、生产备份回滚等
  运维门禁；它们继续由 `.trellis/tasks/08-27-release-environment-validation/`
  跟踪。

## Acceptance criteria

- [ ] 四个页面在亮色和暗色主题下均使用统一冷色 token，正文、控件、边框和状态文本
      满足可读性要求；所有卡片/面板/按钮/输入框/徽标无圆角。
- [ ] 首页、反馈页、WorkTask 页和管理员页在 640px 左右窄屏可单列操作，不出现横向
      溢出；键盘可到达导航、表单、筛选、展开和提交控件，并保留可见焦点。
- [ ] 管理员登录成功后默认显示工作收件箱；刷新、退出、失败登录和主题切换行为不变。
- [ ] 收件箱能合并反馈与 WorkTask 的安全展示字段，默认按更新时间倒序，并能按来源、
      状态、优先级和关键词筛选；无结果、接口失败和超出单次加载范围时有明确说明。
- [ ] 收件箱条目可内联展开详情；现有状态、安排、备注/回复、主页展示和删除动作仍
      走原 API，成功后刷新服务端投影，失败后恢复控件并显示可理解的错误。
- [ ] 公开首页不渲染管理员统计、内部备注、联系方式或账号数据；动态字符串继续经过
      `escapeHtml`/`textContent`，外链保留 `noopener noreferrer`。
- [ ] 现有 SMTP/Webhook 测试、状态设置、导出、分页和通知补偿入口仍可访问且行为不变。
- [ ] `node --check` 覆盖所有修改的页面脚本，`npm test`、`git diff --check` 和
      Trellis 校验通过；完成亮/暗主题、窄屏、键盘、加载/空/错误状态的浏览器冒烟记录。

## Risks and deferred items

- 统一列表若只通过现有分页 API 聚合，数据量很大时可能只覆盖近期记录；必须在 UI 中
  显式标注边界并链接专项视图，若验收要求全量跨来源排序，再单独评估只读聚合接口。
- 共享样式覆盖内嵌 CSS 时可能产生优先级回归；每页需保留 DOM ID/表单字段契约并进行
  亮暗主题和窄屏对照检查。
- 精确对比度需在实际浏览器中复核；若冷色 token 不满足 WCAG 文本对比度，应优先调节
  token 明度而不引入第二套强调色。
- AI Copilot、Kanban/项目管理、用户侧 AI、运维知识 AI 和新的 Account 联动继续按
  `docs/plans/roadmap.md` 的 P1/P2 顺序另建任务。

## Open questions

无阻塞性产品决策；管理员默认入口和收件箱统一列表交互已确认。
