# KWS UI与文案整理实施说明

## 变更边界

本任务只修复展示层的信息架构、布局、视觉一致性和用户可见中文文案。最小行为差距是：管理员设置控件目前混在业务模块中、部分表单横向挤压，公开项目整卡可点击且术语/文案不统一；目标是让这些内容按已确认的模块和入口展示，同时保持现有请求与数据行为不变。

预计修改：

- `public/admin/index.html`：设置选项卡、设置容器、AI/任务/项目表单分组和文案。
- `public/admin/admin.js`：设置模块切换以及动态 AI 配置/项目分区文案。
- `public/workstation.css`：设置、表单、项目列表的网格、间距、响应式和直角控件样式。
- `public/index/main.js`、`public/index.html`：公开项目列表语义与首页徽标。
- `tests/admin-ui-model.test.js`、`tests/project-static-ui.test.js`：静态展示契约回归。
- 当前有效产品、API、架构、测试和项目规范文档：同步“分区”和“AI 配置”表述。

明确不做：服务器 API、数据库 schema、认证权限、AI 请求/提示词、知识库索引、通知发送、KyanetAccount 联动、前端框架或构建步骤变更；不修改 `.env`、数据库、备份和部署目录。

## 执行顺序

1. 先在静态测试中锁定设置选项卡、AI 配置文案、分区术语和公开详情入口契约，确认旧实现按预期失败。
2. 调整管理员 HTML/脚本，把设置内容集中到末尾设置模块，保留所有既有 DOM id、事件、API payload 和权限边界。
3. 调整共享 CSS，使用双列/窄屏单列网格、稳定间距和项目分隔列表；维持冷色、直角、亮暗主题、焦点和无障碍状态。
4. 将主页公开项目从整块链接改为文本 `article` 加单一“查看详情”链接，使用 DOM API 和 `textContent`，保留 public key 编码。
5. 更新当前有效文档中的术语与展示规则，不重写历史归档设计。
6. 执行聚焦静态测试、变更脚本 `node --check`、相关模型测试、`npm test`、`git diff --check`；完成管理员、主页和项目页的亮暗主题、键盘及约 620px 窄屏手工冒烟。

## 验收门禁

- 设置相关控件只在设置模块出现，切换业务模块不重复显示。
- 用户可见 AI 术语统一为“AI 配置”，按钮显示“保存配置”，内部 `profile` API/字段不变。
- “反馈分区”“WorkTask 分区”取代当前页面的“泳道”，两种来源仍保持独立状态。
- 公开项目标题/说明为普通文本，只有“查看详情”可跳转，长文本不水平溢出。
- `KWS Work Hub`、通用知识助手 placeholder、本人任务分组和项目详情间距符合已确认方案。
- 不引入圆角或原生按钮样式回退；动态文本继续经过 `textContent`/`escapeHtml` 边界。

- 本地隔离服务 `127.0.0.1:3010`：主页徽标、亮暗主题和公开入口可见；管理员登录后设置选项卡独立显示，桌面 AI 配置为双列，约 620px 窄屏自动单列，键盘焦点落在 AI 配置字段，页面无水平溢出。
- IAB 浏览器后端在本次会话不可连接，浏览器证据改用本机 Chrome 无头调试通道完成；未访问外网，未发送 SMTP/Webhook 或修改业务数据。
