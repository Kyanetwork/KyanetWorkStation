# 公开项目工作项展示

## Goal

让访问公开项目详情页的访客看到项目主动公开的工作项摘要，而不仅是项目名称、说明、里程碑、更新时间和完成度；同时保持管理员字段、联系方式和内部关系数据不会进入公共响应。

## Confirmed facts

- 当前 `GET /api/public/projects/:publicKey` 仅返回项目基础信息及独立公开开关允许的里程碑、更新时间和完成度，不返回 `project_item`、Feedback 或 WorkTask。
- 管理员项目详情已经能够绑定 Feedback/WorkTask，并按来源类型分区展示；`project_item` 目前只有项目、来源和可选里程碑关联，没有逐条公开字段。
- Feedback/WorkTask 已有标题、状态、公开回复和时间字段；正文、联系方式、管理员备注、账号快照属于敏感或内部字段。
- 当前项目公开设置为基础信息、里程碑、更新时间、完成度四项，旧数据库通过启动时 schema 检查补充结构。
- 项目仅在 active 且基础信息公开时出现在公共页面；公共 API 使用安全 DTO，不返回内部 ID、来源关系或 Kanban 数据。

## Requirements

### R1. 项目级公开工作项开关

- 在项目公开设置中增加“工作项”开关，默认关闭，旧项目迁移后也必须保持关闭。
- 公共工作项只有在项目 active、基础信息公开且该开关开启时才可返回；关闭时响应中不得出现工作项字段，避免通过空列表推断内部数据。

### R2. 逐条公开控制

- 管理员可以在项目详情的 Feedback/WorkTask 关系分区中逐条切换某个已绑定工作项是否公开。
- 新绑定项默认不公开；取消绑定、来源删除、项目归档或项目总开关关闭后，公共页不得显示该项。
- 逐条公开状态只作用于该项目绑定关系，不改变全局首页 `showOnHome` 语义。

### R3. 公共安全投影

- 公共详情按 Feedback 与 WorkTask 分成两个独立分区，保留各自原生状态，不合并为新的 Kanban 状态。
- 每条仅返回来源类型、标题、状态、公开回复（有值时）和必要的公开时间；不得返回正文全文、联系方式、管理员备注、账号快照、内部 ID、项目关系 ID、里程碑内部 ID 或 provider 数据。
- 返回顺序稳定：按来源更新时间降序，同时间按来源 ID 降序；字段缺失时使用安全空值或省略公开回复。

### R4. 管理员与文档

- 管理员项目创建/更新 API、校验器、审计白名单、项目模型和设置界面同步支持项目级开关。
- 逐条公开切换使用管理员会话、同源、JSON 和现有限流/审计边界；审计只记录项目/来源标识和公开状态，不记录正文或联系方式。
- 更新 API 文档、后端/前端 Trellis 规范（如形成新的稳定约定）及测试说明。

## Acceptance Criteria

- [ ] 未开启项目“工作项”公开时，公共详情与现有行为兼容，响应不含 `items`/工作项字段。
- [ ] 开启总开关但没有逐条公开项时，公共详情返回安全的空分区或省略空分区，且不泄露内部数量/ID。
- [ ] 仅被逐条标记为公开的 active Feedback/WorkTask 出现在对应公共分区，标题、状态、公开回复和时间正确，排序稳定。
- [ ] 公共响应及页面 DOM 不包含正文、联系方式、管理员备注、账号快照、内部 ID 或 Kanban/里程碑关系 ID。
- [ ] 管理员可保存项目总开关、逐条切换公开状态，刷新项目详情后状态保持；新绑定项默认关闭。
- [ ] 旧 SQLite/MySQL/PostgreSQL 数据库初始化后自动补充字段，历史项目与工作项默认不公开且数据可正常读取。
- [ ] 覆盖校验、数据库、API、管理员 UI 模型/静态页面和公共页面渲染测试；通过 `node --check`、聚焦测试、`npm test` 与 `git diff --check`。

## Out of scope

- 不复用或改变全局首页 `showOnHome` 开关。
- 不公开工作项正文全文、附件、联系方式、管理员备注、账号信息、内部标识或 Kanban 分区关系。
- 不在本任务引入登录访客、评论、分页、搜索、实时推送或新的前端框架。

## Resolved display decision

- 公共页面每条工作项只展示“更新时间”，不展示创建时间，以保持进展页简洁并减少公开时间信息。
